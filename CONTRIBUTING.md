# Contributing

Thanks for helping improve Awesome Developer Security.

This project is intentionally curated rather than comprehensive. The goal is to maintain a useful collection of high-quality resources for developers and software teams.

## Before Contributing

Please check the existing README before proposing a resource.

A good contribution should:

* Be directly relevant to developer security.
* Provide genuine practical or educational value.
* Have a working official repository or website.
* Have useful documentation.
* Be maintained or otherwise demonstrate meaningful ongoing relevance.
* Provide something that is not already adequately covered by another entry.
* Have a clear and factual description.

Popularity or GitHub star count alone is not enough.

## Adding a Resource

Use this format:

```markdown
- [Project Name](https://example.com/) - Short, objective description of what the resource does.
```

Descriptions should:

* Start with the project's name only in the link text.
* Explain what the resource actually does.
* Focus on its primary use case.
* Avoid marketing claims.
* Avoid unsupported statistics.
* Avoid unnecessary adjectives.
* End with a period.

## Choosing the Correct Category

Add a resource to the category that best represents its primary developer-security use case.

If a resource genuinely belongs in more than one category, prefer listing it once under the category where developers are most likely to look for it.

Avoid duplicate entries unless there is a strong reason.

## Resource Quality

Before submitting a resource, check:

* Is the project real and accessible?
* Is this the official repository or website?
* Is it relevant to developer security?
* Is it documented?
* Is it maintained?
* Is the license clear when applicable?
* Does it provide distinct value?
* Is there already another resource covering essentially the same purpose?

Archived or abandoned projects should generally not be submitted.

## Existing Resources

If a project is already listed, do not submit another link to the same project unless the canonical source has changed.

If two projects perform nearly identical functions, prefer the stronger or more distinctive resource rather than adding both simply to increase the number of entries.

## Commercial Resources

Commercial or proprietary resources may be considered when they provide significant value to developers and fit the scope of the list.

Clearly distinguish proprietary services from open-source projects where necessary.

## Pull Requests

Please keep pull requests focused.

A good pull request should:

* Have a clear title.
* Explain what is being added or changed.
* Include only relevant changes.
* Follow the existing Markdown format.
* Use official links.
* Avoid unrelated formatting changes.

Maintainers may request changes before merging.

## Issues

Use an issue when you want to:

* Suggest a resource.
* Report a broken link.
* Report an outdated description.
* Report an archived or abandoned project.
* Suggest a category improvement.
* Discuss a potential duplicate.

When reporting a resource, include enough information for the maintainer to verify the suggestion.

## Updating Existing Entries

If a project changes its official repository, website, name, scope, license, or major functionality, please submit an update.

Descriptions should be revised when they no longer accurately represent the resource.

## Maintainer Review

Every contribution is reviewed against the project's curation criteria.

A contribution may be declined when:

* It is outside the project's scope.
* It duplicates an existing resource.
* The project is abandoned or archived.
* Documentation is insufficient.
* The official source cannot be verified.
* The resource does not provide enough distinct value.
* The description contains unsupported or promotional claims.

A rejection does not necessarily mean the resource is bad. It may simply not be a strong fit for this particular list.

## Thank You

Every useful contribution helps make developer security resources easier to discover and evaluate.

Thank you for helping keep the list focused, accurate, and useful.
